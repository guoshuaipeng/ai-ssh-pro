### 1.3 明显短板（均有依据）

1. **近期迭代零碎。** `CHANGELOG-UNRELEASED.md` 共 222 个 M 条目，标题含 toast 的有 135 个、含 CmdK 的 36 个；`scripts/` 中 129 个测试脚本名含 toast。0.6.37–0.6.54 又连续 19 个「质感专项」版本。用户能感知的新能力集中在 M20–M25（AI 安全策略与对话）。
2. **国内下载与更新链路不通。** 123 云盘下载尚未上线；应用内「自动」更新通道先查 Gitee（`gitee.com/api/v5/repos/guoshuaipeng/ai-ssh-pro/releases/latest`），2026-10-20 从公网访问返回 404「Not Found Project」，v0.6.36 发布说明里写的 Gitee 地址（CodeYG/ai-ssh-pro）同样返回 404。国内用户实际只能走 GitHub。
3. **对外口径与产品不一致。** 官网和 README 写着「无云同步、无账号」，但 v0.4.0 起已有加密云同步（Gist / WebDAV）；官网主文案「命令只在你确认后运行」与现在的「自动执行」策略不符；README 功能列表仍是 Core-A「命令仅在确认后执行」，没有提三档策略。
4. **安装包体积翻倍。** Windows 安装包从 v0.6.36 的约 86 MB 增至 v0.6.63 的 168 MB，macOS / Linux 包为 181–195 MB。
5. **发布节奏不连续。** Git tag 从 v0.6.36 直接到 v0.6.63，中间 26 个版本没有对应的 Release，用户只能拿到大跨度更新。
6. **Windows 未签名**，发布说明要求用户手动跳过 SmartScreen；macOS 只提供 Apple 芯片版本。
7. **技术债集中。** `App.tsx` 有 10,154 行、`i18n.tsx` 5,787 行、`AIPanel.tsx` 2,389 行，改动的影响面和回归成本都高。

| 维度 | AI-SSH-Pro | Tabby | WindTerm | Termius |

| 平台 | Win / macOS arm64 / Linux | Win / macOS / Linux / Web | Win / macOS / Linux | 桌面 + iOS / Android |

**差异化优势：** 三档 AI 执行策略 + 三层解析 + 主进程只读拦截、AI 对话绑定终端、运维首页 / 告警 / 剧本 / 巡检形成的「AI 运维工作台」、MCP 主机档案、国产 OpenAI 兼容模型可用。竞品的 AI 能力本次没有逐项核实，对外宣传时不应做直接对比。

**基础差距：** 远程 / 动态端口转发、Agent 转发、代理连接是运维用户的常用能力，竞品普遍具备，我们缺失。

## 二、产品方向与目标

**方向：** 以「可管控的 AI 运维助手」为核心差异，先打通分发和口径，再补齐 SSH 基础能力，停止零碎打磨。

**Q4 目标：**

1. 国内用户能从官网一键下载，应用内更新检查在国内网络可用。
2. 官网、README、发布说明与实际功能一致，推广（CSDN、dev.to）只讲真实存在的能力。
3. AI 执行全程可追溯：每条 AI 命令有记录、能复盘、能随时停止。
4. 补齐远程 / 动态端口转发和 Agent 转发，消除与竞品的基础差距。
5. 迭代以「功能主题」为单位，每个版本都有对应的 Release，不再单独发 toast 级别的版本。

## 五、需要负责人拍板的问题

1. **国内分发与更新源：** 123 云盘只能放下载文件，没有版本查询接口。应用内更新检查用哪个国内源？
   - A. 恢复公开的 Gitee 仓库与 Release，作为更新接口；
   - B. 在官网（GitHub Pages）放一个版本 JSON，下载链接指向 123 云盘；
   - C. 国内只提供下载，更新检查仍走 GitHub。
   建议选 B：维护成本最低，也不依赖 Gitee 仓库状态；前提是实测官网在国内网络可以稳定访问，否则选 A。
2. **Windows 代码签名是否投入费用：** 签名证书需要年费，但能去掉 SmartScreen 拦截，提升下载后的安装成功率。是否在 Q4 投入？
3. **迭代 2 与迭代 3 的先后顺序：** 先做「AI 执行审计与控制」，强化差异化、配合推广；还是先补「远程 / 动态端口转发」，减少用户流失？本计划按「先 AI 后连接」排序。
