# 开发规则（每轮开始前先读）

来源：docs/retro.md。新增规则时在条目末尾注明来源事项。

## 流程
1. 每轮开始前读本文件与 docs/retro.md 最近 5 条；每轮结束、每修完一个 bug，追加一条复盘。
2. 提案前必须去重：grep docs/iterations、docs/backlog.md 和 src，至少用 2 个同义词，并在提案里写明查过的词与命中结果。（重复需求）
3. 需求中途变更时，先回报新的估时，再动手。（分屏改版）
4. 迭代期只跑相关测试；全量 `npm test` 只在最终 HEAD 跑一次，必须全绿。（分屏改版）
5. 只在本地提交，不推送；只按明确路径暂存，不提交用户原有的未跟踪文件。

## 代码
6. 会被多次触发的回调（切换、菜单动作）读 ref 的最新值，并在处理函数内同步写回 ref；不依赖 useCallback 依赖数组的正确性。（分屏旧状态）
7. 弹层自动关闭只能在状态变化的边沿触发（用 ref 记录上一次值），不能由「当前状态」持续触发；改入口显示条件时，grep 同一状态的所有 effect。（全部标签）
8. 向远端 shell 写入内容的功能，必须在真实 bash 交互式 tty 中验证回显和 history；需要隐藏的内容必须有结束标记和渲染层闸门。（Shell 集成）
9. 删除类操作必须可确认或可撤销；AI 输出只预填，不自动执行；尊重只读和写保护。

## 测试
10. 切换类功能至少覆盖：连续两次、快速三次、切换上下文后再操作。（分屏旧状态）
11. 每个弹层至少有一条「打开后保持打开」和一条「点击外部关闭」的测试。（全部标签）

## UI 与截图
12. 改 UI 前先加截图场景并单独提交，立即拍 before，再改代码；不用 stash 拍 before，需要旧版时用 git worktree。（剧本截图）
13. 截图场景必须幂等：先读状态，再决定是否点击。（分屏改版）
14. UI 交付前用 Electron 截深色和浅色，对照视觉清单：不折行或错位；不出现原生 select；可见文字按钮不超过 3 个；同一信息不重复；标签和控件对齐；间距、字号用 token；文案为正式中文，中英同步提交。（界面乱）
15. 每 3 轮做一次全页面视觉审查，结果写入 backlog 并排序。（界面乱）
16. 多项共改一个文件时，改完一项立即提交，再开始下一项，保证每项一个提交。（第 44 轮）
17. 改弹层的打开、关闭或层级前，先 grep 所有弹层实现（createPortal、BuiltMenu、openContextMenu、App 自管菜单状态），列出拥有者；关闭只走 closeContextMenu 广播的 `aiss:close-menus`，新菜单必须监听。（第 45 轮）
