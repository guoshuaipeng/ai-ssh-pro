# v0.7.0 分发与文案对齐 · 交互方案

状态：**已实现**。基线：`feat/polish-14-chrome-sweep` @ `49a8676`（tag `v0.6.63`）。本迭代不涉及代码签名。

## 1. 目标

国内用户检查更新时不再依赖已 404 的 Gitee Releases API。客户端优先读官网更新清单，失败再回退 GitHub Releases；更新提示改为深色自绘弹层，文案正式；有缓存时先出示上次结果，不出现「加载中」。

## 2. 更新源

| 通道 | 行为 |
| --- | --- |
| **自动**（默认） | 先读 `https://guoshuaipeng.github.io/ai-ssh-pro/update.json`，失败 / 超时 / 非 200 再读 GitHub `releases/latest` |
| **仅官网清单** | 只读官网 JSON |
| **仅 GitHub** | 只读 GitHub Releases API |
| **自定义清单** | 用户填写的 http(s) URL，同时接受官网清单与 GitHub Release JSON |

已保存的「仅 Gitee」通道启动时迁移为「自动」。Gitee 仓库链接仍可在关于页作为源码镜像出现，**不再作为更新探测接口**。

不做应用内静默安装、不做代码签名。下载始终打开系统浏览器。

## 3. 清单格式

见 [docs/update-manifest.md](../update-manifest.md)。仓库示例：`docs/website/update.json`（部署到 gh-pages 根路径即为 `…/update.json`）。

必填：`version`、发布说明、各平台 GitHub 资源地址、123 云盘分享链接（可按平台或全局一份）。

## 4. 检查更新 · 交互

```
用户点「检查更新」
  ├─ 有缓存 → 立刻出示缓存结果，旁注「上次 · N 分钟前」
  └─ 同时后台请求官网（及回退）
       ├─ 成功 → 替换为新结果，去掉「上次」或改为「刚刚」
       └─ 失败 → 若有缓存则保留缓存；无缓存再报失败
```

硬性规则：

- 按钮文案始终是「检查更新」，**不出现**「检查中…」「加载中」。
- 启动静默检查不弹 toast；手动检查有新版本才开弹层，已是最新才 toast「当前已是最新版本 vX」。
- 缓存写在本机 `localStorage`（`aiss.update.cache`），不是 HTTP 缓存。

## 5. 更新提示弹层

深色主题自绘（沿用 `.modal-backdrop` 以便叠层计数，面板本身独立样式）。

```
┌──────────────────────────────────────────┐
│  有可用更新                           ✕  │
│  v0.7.0 · 来源：官网清单                 │
│                                          │
│  · 分发改为官网清单优先                  │
│  · 国内可走 123 云盘                     │
│                                          │
│  上次 · 3 分钟前                         │
│                                          │
│  [123云盘下载]     [跳过] [稍后提醒] [前往下载] │
└──────────────────────────────────────────┘
```

- 间距 / 圆角：`--space-*`、`--radius-dialog`。边框只用 `--color-border-default` 一线，不再加粗描边。
- 「前往下载」打开当前来源的 GitHub / 清单下载地址。
- 「123云盘下载」仅当清单提供 `pan123` 时出现；国内用户可选，不强制。
- 「稍后提醒」关弹层；「跳过此版本」记住版本号，静默检查不再提示。
- 文案正式：不用「发现新版本啦」一类口语。
