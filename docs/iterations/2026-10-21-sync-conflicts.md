# D67 同步冲突处理

核对：D62 只把「目标较新」的文件标出来并默认不勾选，用户没法选择「保留目标端」→ 真实缺口。
限制：同步没有记录上次同步时的基线，所以无法严格判断「两端都改过」。这里用「已修改，且目标端 mtime 更新」近似代表冲突，并在文档里写明。
设计：
- 冲突行用下拉框代替勾选框，三个选项：
  - 跳过（默认，两端都不动）
  - 用源端覆盖
  - 保留目标端：这一行反向复制，把目标端较新的文件取回到源端。
- shared/folder-sync 新增 resolvePlanRows：给选择「保留目标端」的行打上 reverse 标记。反向的行只复制，永远不触发删除。
- SftpPanel.runSync 按行决定方向。反向上传覆盖远端前，照旧先拍远端快照。
- 汇总栏显示「n 个冲突：目标端较新，默认跳过」。
- 删除仍默认关闭，生产主机删除前仍要输入主机名。
后续（D67b）：每次同步后保存一份基线，就能准确识别两端都改过的文件。
