# S41 分屏工具栏改版

## 问题（来自用户截图）
- 标签栏下方单独占一整行工具栏，在笔记本屏幕上浪费了约 28px 的纵向空间，而且它和两个窗格各自的标题条叠在一起，等于有两层标题。
- 控件样式不统一：原生 `<select>` 不符合主题 Select 规范，几个文字按钮也各不相同。
- 「左右」按钮看起来像状态标签，看不出点击后会切换方向。
- 「交换」灰掉了，却不说明原因。
- 广播状态只是一段纯文字，不能点击。
- 两个窗格的标题一样，看不出哪个是主屏，也看不出键盘输入在哪个窗格。

## 设计
1. **去掉工具栏行，控件放进窗格标题条。** 每个窗格的标题条显示本窗格的信息。所有窗格共用的控件只放在左侧（第一个）窗格标题条的右端，位置固定，不随交换跳动。
2. **角色徽标。** 每个窗格的标题条最前面显示「主屏」（强调色描边）或「副屏」（中性描边）。交换两侧后，徽标跟着会话走，不跟着位置走。
3. **副屏用主题 Select 选择会话。** 可选「镜像当前会话」（右侧提示「同一会话，仅显示」）或其他已连接的会话。下拉框直接放在副屏标题条里，选择的东西和它影响的窗格在同一处。
4. **图标按钮。** 方向、交换、均分、关闭分屏都改成 22px 的图标按钮，悬停时提示说明当前状态和点击后的效果，例如「当前为左右分屏，点击切换为上下分屏」。禁用的按钮外包一层元素承载提示，所以灰掉时也能看到原因，例如交换按钮会提示「镜像模式下两侧为同一会话……」。均分在已经是 50/50 时灰掉。
5. **广播开关胶囊。** 胶囊可点击，并标为开关控件（role="switch" + aria-checked）。开启时用警示色，同时两个窗格整体加警示色描边，避免误把命令敲进两台主机。点击走现有的 toggleBroadcast：开启时先弹出目标选择，关闭时直接关闭。
6. **焦点。** 保留 IX-6 的标题条顶部 2px 强调线，窗格内容区再加 1px 强调色内描边，标题条上显示一个焦点圆点（提示「键盘输入当前在此窗格」）。广播开启时，聚焦的窗格描边加粗为 2px 警示色。
7. **关闭分屏的 ×。** 和标签栏的分屏按钮走同一条路径：App 里的 `handleTitlebarMenuActionRef.current('toggleSplit')`，由它读取最新的 `splitEnabledRef`。上一次修好的分屏开关逻辑没有改动。

## 约束
- 只用 spacing、颜色、圆角 token 和主题 Select，不出现原生 select。
- 文案用正式中文，并提供英文对照。
- 界面上没有加载态。

## 补充（S41b）：标签栏的分屏按钮改为模式入口
- **用户要求**：标签栏最右侧、「全部标签」左边的分屏按钮，改为分屏模式的切换入口。
- **交互**：
  - 点击按钮弹出主题 popover，有三个选项：关闭分屏、左右分屏、上下分屏。当前模式打勾；选项使用 menuitemradio 和 aria-checked，支持上下键选择，Esc 关闭。
  - 按钮图标随模式变化：单框表示关闭，竖线表示左右，横线表示上下。tooltip 显示「分屏模式：当前模式。点击选择」。
- **理由**：方向本来就是分屏模式的一部分。原先按钮只能开或关，方向按钮却放在窗格标题条里，两个入口割裂。合成一个入口后，「现在是什么模式」和「怎么改」都在同一处。
- **去掉重复入口**：窗格标题条里的方向按钮和关闭 × 都去掉了，统一从这个入口操作。标题条只保留与窗格本身有关的控件：角色徽标、会话选择、广播、交换、均分。菜单「视图 → 分屏」和快捷键仍然可以开关分屏，方向沿用上次的选择。
- **「→」按钮**：它是标签条的横向滚动按钮（tab-scroll-right），只在标签溢出时出现，与分屏方向无关，保持不变。
- **状态**：方向从 SplitTerminalView 移到 App 管理（`splitOrientation`，持久化键仍是 `aiss.split.orientation`）。选择时通过 `applySplitMode` 读取 `splitEnabledRef` 和 `splitOrientationRef` 的最新值，连续快速选择也能正确切换。原有的 toggleSplit 路径（`applySplitToggle`）不变。
- **popover 关闭逻辑**：点击外部的判断以整个包裹元素为界，按钮本身在包裹元素内，所以点击按钮不会同时触发打开和关闭。
