# D107：Shell Integration 注入脚本对用户不可见（2026-10-21）

## 现象
连接 bash 主机（如 `[root@test_java01 ~]#`）后，终端中原样显示 `if [ -n "${ZSH_VERSION:-}" ]; then __aiss_si(){ ... fi`，随后再出现一个提示符。

## 根因
注入方式是向交互式 shell 直接写入一行命令。远端 tty 的行规程开启了回显，写入的每个字符都会被原样回显到终端；渲染层对这段回显没有任何处理，因此用户看到整行脚本，执行后 shell 又输出新的提示符。此外仅靠前导空格避免记入历史，依赖 `HISTCONTROL=ignorespace`，CentOS 等默认配置下该行仍会留在历史中。

## 方案（选择最稳妥的渲染层隐藏 + 结束标记）
- `stty -echo` 不可行：`stty` 命令本身也是输入的一部分，在其生效之前同样会被回显。exec 通道或临时文件无法改变交互式 shell 本身的提示钩子，且临时文件需写服务器磁盘，与「不修改服务器文件」的约定冲突。
- 脚本末尾输出私有 OSC 结束标记 `ESC ]6973;aiss-si BEL`。回显中出现的是转义文本 `\033`，不含真实 ESC，不会误判。
- 渲染层写入前派发 `aiss-si-gate`，该会话所有窗格（含分屏镜像）开启回显闸门：收到结束标记前的输出全部隐藏；收到后清除原提示符所在行，由 shell 新输出的提示符原位替代，视觉上无变化。
- 不支持的 shell（fish、sh、网络设备）收不到标记：5 秒后只显示最后一行（即其提示符），不再展示报错与脚本。
- bash 分支执行 `builtin history -d` 删除该行，不依赖 `HISTCONTROL`；zsh 仍依赖前导空格。
- 首个 `133;E` 为历史中的旧条目，忽略，不当作新输入的命令。
- 每个会话只注入一次（`wasInjected`）；重连或复制会话为新 shell，重新注入时同样被隐藏。

## 测试
`scripts/test-si-hidden.ts`：闸门的分片、跨块标记、超时回退，脚本前导空格、历史删除与结束标记，渲染层接线。
