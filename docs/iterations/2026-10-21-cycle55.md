# 第 55 轮：打开连接（含批量和二次确认）、从历史填入、SFTP 定位目录，以及 AI 动作测试加严

## 交付
1. `connection.open`：targets 可写多个（逗号、顿号、分号或空格分隔），任意一个找不到就整体不执行。3 台及以上视为高风险：第一次点击后进入「再次确认」状态，4 秒内不点就自动恢复，期间修改参数也会重置。机制是通用的：`ActionDef.risk` 加上卡片的 armed 状态。
2. `history.fill`：所有关键词都必须命中；同一主机的结果优先，其次按最近使用、使用次数排序。只填入命令栏，不发送；没有会话时报错。
3. `sftp.open` 新增 path：必须以 / 或 ~ 开头。用现有的 `requestSftpGoto` 跳到目录，面板晚于跳转请求加载时也能生效。
4. 观感项：卡片的「取消」按钮改用 Button ghost 组件，和主按钮保持一致；二次确认提示原本挤在底栏里被截断，改为单独一行显示。
5. dev-rules：把 c54 复盘的两点改进写入第 5、6、12 条，把 AI 动作的测试标准写入第 10 条，总数仍为 15 条。

## 端到端测试和评测发现的问题（都已修复，除最后一条）
- 命令栏的 `useRef` 写在折叠状态的 early return 之后。命令栏由「填入」打开时触发 React #310，整个界面白屏。这是 D85 引入的老 bug，已把 hook 移到 return 之前。
- `snippet.create` 执行后切到片段面板，AI 卡片随之消失，看不到执行结果。改为停留在 AI 面板，只显示 toast。
- 端口转发失败时，原样显示 "Error invoking remote method…"。现在用 `cleanIpcError` 去掉前缀。
- 真实模型评测发现，模型常把动作名直接写进 action 字段。`proposalFromReply` 现在兼容这种格式，提示词里也加了示例。
- **未修复**：浅色这一轮（与深色共用同一份数据，且已有演示会话）里，`snippet.create` 点「确认执行」没有反应，可以稳定复现。限时 10 分钟没查出原因，已放进 backlog，第 56 轮 P0。
