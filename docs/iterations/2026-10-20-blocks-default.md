# D18 输出分块默认开启评估 + 首次提示

**结论：保持默认关闭，增加一次性、非打扰的提示。**

**理由**
1. 垂直空间：分块条默认占终端高度 25%（最低 72px）。运维常用 `tail -f`、`top`、日志滚动，默认就少四分之一可视行，对所有用户都是成本。
2. 准确性依赖环境：直接键入命令的分块靠提示符解析（D10），自定义 PS1 / 主题下可能漏判；退出码需要命令栏标记或 Shell Integration（D11/D14，后者默认关）。默认开会把这些边界情况暴露给所有人。
3. 可逆、可发现即可：功能对需要的人价值高，问题是"不知道有"，用提示解决发现问题，比默认开更稳。
4. 已有测试和说明都约定"默认关闭"（L5）。

**提示设计**
- 触发：本次运行中提交满 3 条命令（命令栏或直接键入，不含演示主机），且分块未开启、从未提示过。
- 形式：普通 toast（12 秒），一个「开启」按钮；不弹窗、不抢焦点、只出现一次（`aiss.blocks.hintShown`）。
- 文案：「可开启「输出分块」：按命令分组显示输出与退出码，支持复制、搜索和询问 AI。可随时在「会话」菜单中关闭。」
