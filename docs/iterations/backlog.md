# 需求池（PM 提案，未实施）

更新：2026-10-20。以下三项按优先级排列，依据均来自路线图、现有代码或本轮实测，未使用任何虚构的用户数据。

## B1 · AI 命令退出码采集（补全 2.3 / 2.2 的执行判定）　P0

- **问题**：`readConfirmedCommandOutcome()`（`src/main/core-a-command-failure.ts`）依赖 SSH 管理器的 `confirmedCommandOutcome` 探针，代码注释写明「生产 SSH 管理器未实现」。因此本轮上线的执行回放在真实主机上几乎都显示「已执行」，无法区分成功与失败；`classifyCommandFailure` 的非零退出判定、「连续两次失败拒绝」也只能在写入失败时生效。
- **用户故事**：作为开启自动执行的运维，我希望 AI 执行的每条命令都有明确的成功 / 失败和退出码，复盘时不必逐条翻终端。
- **方案方向**：AI 写入命令时追加不可见的 shell 集成标记（如 OSC 133;D;$? 或一次性 `printf` 哨兵），主进程在输出流中解析并剥离，交互式命令（vim / top 等，已有 `isInteractiveCommand`）不追加。
- **验收标准**：bash / zsh / sh 三种 shell 下，`true` / `false` / 超时三类命令的回放分别显示成功 / 失败·退出码 1 / 失败（超时）；终端上不出现标记字符；关闭该功能时回退到现在的「已执行」。

## B2 · 模型接入预设（路线图 2.5）　P1

- **问题**：目前接入模型需要手填 base URL 与模型名（`AiConfigForm.tsx`），路线图把它列为影响首次配置成功率的问题；迭代 2 中只剩这一项未做。
- **用户故事**：作为第一次使用的用户，我希望从列表里选「通义千问 / DeepSeek / Kimi / 本地 Ollama」等预设，只填 Key 就能开始对话。
- **验收标准**：选择预设后自动填好 base URL 与默认模型，只需填 Key（Ollama 不需要 Key）；预设下拉使用主题弹层；保存后可立即在 AI 面板对话；预设表为本地静态数据，不联网拉取。

## B3 · 远程端口转发 -R（路线图 3.1）　P0（迭代 3 首项）

- **问题**：`port-forward.ts` 只用 `forwardOut` 实现本地转发；路线图 1.4 对比显示 Tabby、WindTerm 都支持远程 / 动态转发，是运维常用能力的基础差距。
- **用户故事**：作为需要把本机服务暴露给远端调试的开发 / 运维，我希望在端口转发页新建「远程转发」，远端端口即可访问我本机的服务。
- **验收标准**：可新建 / 停止远程转发并显示连接数与流量；断线重连后按配置恢复；只读主机遵守现有保护规则；转发的建立与停止写入审计。
