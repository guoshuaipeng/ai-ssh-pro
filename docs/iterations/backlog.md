## C1 · 动态端口转发 SOCKS5 -D（路线图 3.2）　P0

- **问题**：B3 之后，转发面板支持 -L 和 -R，但代码里仍然没有 SOCKS 实现。访问内网 Web 控制台（K8s Dashboard、Grafana、BMC）是运维最常用的场景，现在只能一个端口配一条 -L。
- **用户故事**：作为运维，我在转发面板选择「动态 -D」并填一个本地端口。浏览器把 SOCKS5 代理设成 127.0.0.1:端口 后，就能经目标主机访问内网任意地址。
- **方案方向**：在 `forward-manager.ts` 中加 `startDynamicForward`。本地 `net` server 实现 SOCKS5 握手（RFC 1928：无认证；CONNECT；IPv4、域名、IPv6），每个连接调用一次 `forwardOut(dstHost, dstPort)`。分段控件增加第三项 -D，行内统计连接数、流量，并显示最近访问的目标。重连恢复复用 B3 的 CarryStore。
- **验收标准**：curl `--socks5-hostname` 能通过假 client 和本机 echo 完成单测；不支持的 BIND、UDP ASSOCIATE 返回 0x07；只监听 127.0.0.1；只读主机允许使用（不改动服务器），但每条 -D 写一条审计；面板显示「浏览器代理设置」复制按钮。

## C2 · 原生下拉清理第一批（界面债）　P1

- **问题**：设计规范要求使用主题弹层，不用原生 select。但 `src/renderer` 下仍有 46 处 `<select>`（2026-10-20 统计）。本轮截图里明显的有：AI 设置的「当前 Provider」「当前使用的模型」、端口转发的「会话」、审计页筛选、运维首页「全部连接」。在深色主题下，系统下拉框是白底，和界面割裂。

- **验收标准**：5 处替换完成，截图在两种主题下一致；键盘可以完成选择；`check-ux` 新规则启用并记录基线。

## C3 · SSH Agent 转发（路线图 3.3）　P1

- **问题**：现在只支持用 Agent 认证，不能把本机 Agent 转发到远端。经跳板 `ssh` 到下一跳，或在服务器上 `git pull` 私有仓库时，用户只能把私钥拷到服务器上，这更危险。
- **用户故事**：作为运维，我在某台主机的连接配置里打开「转发 SSH Agent」，看到风险说明后确认。之后在远端可以用本机 Agent 里的密钥继续 `ssh`。
- **方案方向**：ssh2 的 `agentForward: true` 加 `agent` socket；按主机配置，默认关闭；只读和生产主机开启时需要二次确认；开关变化写审计；终端状态栏显示 Agent 转发的标记。
- **验收标准**：默认关闭；开启后远端 `ssh-add -l` 能列出本机密钥（需要真实环境验证）；关闭后列不出；开关和每次会话的启用都有审计记录。
