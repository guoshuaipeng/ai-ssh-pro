# B1 补充：隐藏退出码采集后缀的回显 —— 结论：暂不可行，保留设置

## 现状
AI 写入命令时会追加 `; printf '\033]777;aiss-exit;<nonce>;%d\007' $?`。
- 这段 printf 输出的 OSC 标记已经由主进程剥离，xterm 也会忽略未知的 OSC，所以标记本身不可见。
- 但回显出来的命令行是远端 TTY 或 readline 对“输入字符”的回显，因此后缀文字可见。
- 给 AI 的快照和录制文本里的后缀已经通过 `stripEchoedMarker` 去掉。

## 评估过的方案
| 方案 | 问题 |
|---|---|
| `stty -echo` 包裹命令 | `stty -echo` 这一行在生效前就已经被回显了。如果命令被中断、没能恢复 echo，用户终端会失去回显，风险高。交互命令也会受影响。 |
| 单独的 exec 通道采集 | 拿不到交互 shell 的 `$?`、cwd、环境变量和别名，得到的退出码不是用户看到的那条命令的。 |
| 注入 PROMPT_COMMAND / precmd | 需要改写用户 shell 的状态，可能覆盖用户已有的 PROMPT_COMMAND 或 starship 等配置。zsh、fish、busybox sh 的行为各不相同。注入那一行本身也会被回显一次。 |
| 前导空格 + HISTCONTROL | 只能让后缀不进入历史记录，对回显不起作用。 |
| 在送给 xterm 的流里删掉回显后缀 | 现在送给 xterm 的是原始 Buffer，删除需要改成发送清洗后的文本。终端宽度折行时，readline 会插入 `\r`、`ESC[K` 等重绘序列，没法可靠匹配。匹配失败会出现半截残留，或者误删用户输出，属于高风险。 |

## 结论
在没有远端 shell integration（类似 VS Code / iTerm 那样一次性安装 hook）的前提下，没办法可靠地隐藏回显。
- 保留“采集 AI 命令退出码”这个设置，设置里已经说明了回显的问题，用户可以关闭。
- 后续方向：做可选的“shell integration”，由用户显式开启，会话开始时注入一次 precmd hook，之后就不需要追加后缀。已经列入 backlog 候选。
